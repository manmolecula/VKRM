# Практическая реализация методики миграции Vue.js приложения

Данный репозиторий содержит практическую часть выпускной квалификационной работы на тему: **«Разработка методики миграции и рефакторинга высоконагруженного веб-приложения на Vue.js с переходом к современной архитектуре на основе композиционных функций»**.

В рамках работы проведен сравнительный анализ двух подходов к разработке на примере реальных компонентов системы различного уровня сложности (исходный код анонимизирован).

## Структура проекта

### Пример 1: Компонент работы со списками (Низконагруженный компонент)
Демонстрация рефакторинга стандартного компонента с сетевой загрузкой и пагинацией.
* `src/SingleComponent.vue` — Исходная реализация (Vue 2, Options API). Логика работы с сервером и состояние формы тесно связаны в одном модуле.
* `src/MigratedSingleComponent/` — Рефакторинг (Vue 3, Composition API).
  * `MigratedSingleComponent.vue` — Компонент представления.
  * `composables/useMigratedSingleComponentLogic.js` — Изолированная логика запросов и вычисления диапазона страниц.

### Пример 2: Компонент со смешанной ответственностью (Высоконагруженный компонент)
Демонстрация применения методики к компоненту с нарушением принципа единой ответственности (смешение управления интерфейсом, бизнес-правил и глобального состояния).
* `src/MultiComponent.vue` — Исходная реализация (Vue 2). Характеризуется жесткой связностью с хранилищем Vuex и зависимостью от глобального объекта `window`.
* `src/MigratedMultiComponent/` — Рефакторинг (Vue 3).
  * `MigratedMultiComponent.vue` — Компонент, зависящий только от передаваемых данных.
  * `composables/useMigratedMultiComponent.js` — Бизнес-логика контроля доступа и фильтрации, полностью независимая от фреймворка.

* `tests/` — Набор сравнительных модульных тестов.

## Запуск проекта и тестов

1. Установка зависимостей:
```bash
npm install
```

2. Запуск тестов:
```bash
npm test
```

3. Запуск метрик:
```bash
npm run metrics
```

## Результаты миграции и количественные метрики

Для оценки результатов используются метрики тестирования, так как главная цель рефакторинга — изоляция бизнес-логики и упрощение поддержки кода.

### Описание метрик

Перед рассмотрением данных ознакомьтесь с определениями используемых метрик:

| Метрика | Описание | Единица измерения |
|---------|----------|-------------------|
| **Объем кода тестов** | Количество строк кода, необходимое для покрытия компонента тестами | строки |
| **Время выполнения тестов** | Среднее время запуска набора модульных тестов | миллисекунды (мс) |
| **Необходимые зависимости** | Количество внешних зависимостей (mock-объектов, имитаций), требуемых для тестирования | количество элементов |
| **Обработка больших массивов** | Тип реактивности, используемый для работы с данными | тип механизма |
| **Коэффициент связанности (DCR)** | Dependency Coupling Ratio — сумма всех внешних зависимостей для тестирования | абсолютное значение |
| **Индекс тестируемости (TI)** | Testability Index — отношение строк бизнес-логики к затратам на инфраструктуру теста | коэффициент |
| **Сокращение бизнес-логики (CR)** | Code Reduction — изменение объема бизнес-логики после миграции | коэффициент |

## Дополнительные количественные метрики качества архитектуры

Для более глубокого анализа эффективности методики миграции введены три специализированные метрики, оценивающие архитектурные улучшения.

### Метрика 1: Коэффициент связанности зависимостей (Dependency Coupling Ratio, DCR)

Показывает количество внешних зависимостей, необходимых для тестирования единицы логики. Рассчитывается как сумма всех зависимостей: имитации UI-компонентов + модули Vuex + глобальные объекты + подменные функции.

**Формула:** `DCR = Σ(имитации UI) + Σ(модули Vuex) + Σ(глобальные объекты) + Σ(подменные функции)`

#### Данные метрик

| Компонент | Имитации UI | Модули Vuex | Глобальные объекты | Подменные функции | **Общий DCR** | Изменение |
|-----------|-------------|-------------|--------------------|-------------------|---------------|-----------|
| SingleComponent (Vue 2) | 12 | 0 | 2 (`$t`, `$style`) | 1 | **15** | — |
| MigratedSingleComponent (Vue 3 Options+Comp) | 0 | 0 | 0 | 1 | **1** | **▼ в 15 раз ниже** |
| MigratedSingleComponent (Vue 3 Composition) | 0 | 0 | 0 | 1 | **1** | **▼ в 15 раз ниже** |
| MultiComponent (Vue 2) | 23 | 1 | 3 (`window.*`) | 4 | **31** | — |
| MigratedMultiComponent (Vue 3 Options+Comp) | 0 | 0 | 0 | 1 | **1** | **▼ в 31 раз ниже** |
| MigratedMultiComponent (Vue 3 Composition) | 0 | 0 | 0 | 1 | **1** | **▼ в 31 раз ниже** |

#### Графическое представление

```

│  Низконагруженный компонент                                         │
│  Vue 2 (Options API)        ████████████████████████  15            │

### Метрика 2: Индекс тестируемости (Testability Index, TI)

Комплексная метрика, оценивающая эффективность тестирования через отношение проверяемой бизнес-логики к накладным расходам на инфраструктуру теста.

**Формула:** `TI = (Строки бизнес-логики) / (Строки теста + Строки подменных функций + Строки имитаций компонентов)`

Где «строки бизнес-логики» — это строки кода, непосредственно участвующие в проверке сценария (composable функция или методы компонента).

#### Данные метрик

| Компонент | Строки бизнес-логики | Строки теста | Строки инфраструктуры* | **TI** | Изменение |
|-----------|----------------------|--------------|------------------------|--------|-----------|
| SingleComponent (Vue 2) | 87 | 95 | 17 (имитации + подмены) | **0.78** | — |
| MigratedSingleComponent (Vue 3 Options+Comp) | 73 | 71 | 0 (только подмена API) | **1.03** | **в 1.3 раза эффективнее** |
| MigratedSingleComponent (Vue 3 Composition) | 107 | 71 | 0 (только подмена API) | **1.51** | **в 1.9 раза эффективнее** |
| MultiComponent (Vue 2) | 232 | 128 | 33 (хранилище + window + имитации) | **1.44** | — |
| MigratedMultiComponent (Vue 3 Options+Comp) | 85 | 58 | 2 (только подмена API) | **1.42** | **в 1.0 раз эффективнее** |
| MigratedMultiComponent (Vue 3 Composition) | 114 | 39 | 2 (только подмена API) | **2.79** | **в 1.9 раза эффективнее** |

*\*Инфраструктура включает: имитации компонентов, настройки Vuex, подмену глобальных объектов, конфигурацию mount*

### Метрика 3: Сокращение бизнес-логики (Code Reduction, CR)

Оценивает изменение объема бизнес-логики после миграции на Composition API. Показывает, насколько сократился или увеличился код бизнес-логики.

**Формула:** `CR = (Vue2 логика - Vue3 логика) / Vue2 логика`

#### Данные метрик

| Компонент | Vue2 логика | Vue3 Options+Comp | CR% (Options) | Vue3 Composition+Comp | CR% (Composition) | Изменение |
|-----------|-------------|-------------------|---------------|----------------------|-------------------|-----------|
| SingleComponent | 87 | 73 | **16.1%** (сокращение) | 107 | **-23.0%** (увеличение) | **▲ увеличение в 1.2 раза** |
| MultiComponent | 232 | 85 | **63.4%** (сокращение) | 114 | **50.9%** (сокращение) | **▼ сокращение в 2.0 раза** |

```

**Вывод:** Для высоконагруженного компонента бизнес-логика сократилась **в 2.0 раза**, что свидетельствует об оптимизации кода. Для низконагруженного компонента объем увеличился в 1.2 раза из-за выделения composable для лучшей тестируемости.

## Анализ качества тестирования

Сравнение проводилось на идентичных сценариях для обоих компонентов:

**Single Component (Низконагруженный компонент):**
- Фильтрация табличных данных
- Проверка пагинации и вычисления диапазона страниц
- Валидация сетевого запроса и обработки ответа

**Multi Component (Высоконагруженный компонент):**
- Фильтрация табличных данных
- Проверка прав доступа (определение визуального состояния элемента по статусу пользователя)
- Контроль доступа к функциональным блокам

### Проблемы верификации в исходной архитектуре (Vue 2)
Для проверки элементарного правила определения доступа требовалась комплексная подготовка инфраструктуры:
1. **Инициализация хранилища:** Необходимость создания полноценного экземпляра Vuex с описанием модулей, даже если проверяемое правило не взаимодействует со стором напрямую.
2. **Зависимость от среды:** Подмена глобального объекта `window`, что снижает надежность тестов при параллельном запуске и усложняет их поддержку.
3. **Избыточная инициализация:** Использование инструмента `shallowMount` и обязательное описание более 20 имитаций компонентов (таблиц, диалоговых окон), которые не участвуют в проверке, но необходимы для парсинга шаблона.

### Преимущества верификации после рефакторинга (Vue 3)
Разделение ответственности позволило вынести проверяемые правила в независимые функции (`use...`).
* **Скорость:** Время выполнения сократилось до 2–3 миллисекунд за счет исключения этапов инициализации виртуального DOM.
* **Изоляция:** Данные для проверки (например, статус авторизации) передаются в функцию как аргумент. Тест полностью абстрагирован от среды выполнения (браузер/сервер).
* **Читаемость:** Тестовый сценарий сводится к проверке возвращаемого значения функции, что соответствует классическим принципам модульного тестирования.

## Архитектурные выводы

Примененная методика поэтапной миграции позволила достичь следующих результатов:

1. **Снижение когнитивной сложности:** Разделение модуля на уровень представления и уровень логики. Разработчику достаточно изучить функцию composable для понимания бизнес-правил, не анализируя шаблон компонента.
2. **Оптимизация производительности:** Применение механизма `shallowRef` для хранения больших массивов данных исключило избыточное рекурсивное отслеживание изменений внутри элементов списков, что снижает нагрузку на процессор и сборщик мусора.
3. **Устранение жесткой связанности:** Компоненты больше не зависят от конкретной структуры глобальных переменных или модулей состояния (Vuex). Передача конфигурации через аргументы делает логику переносимой между различными частями приложения.
4. **Повышение тестируемости:** Методика перевела процесс проверки бизнес-логики из разряда интеграционных тестов (требующих подъема инфраструктуры) в разряд быстрых модульных тестов. Это гарантирует отсутствие регрессий при дальнейшей поддержке системы.
5. **Количественное подтверждение эффективности:** Введенные метрики (DCR, TI, CR) демонстрируют улучшение архитектурных характеристик в 1.2–31 раз по ключевым показателям связанности, тестируемости и сокращения бизнес-логики.
