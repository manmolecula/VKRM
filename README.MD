# Практическая реализация методики миграции Vue.js-приложения

Данный репозиторий содержит практическую часть выпускной квалификационной работы на тему: **«Миграция и рефакторинг высоконагруженного веб-приложения на Vue.js с переходом к современной архитектуре на основе композиционных функций»**.

В рамках работы проведен сравнительный анализ двух подходов к миграции и архитектурному рефакторингу Vue.js-компонентов. Исходный код анонимизирован и представлен в виде компонентов различного уровня сложности. Первый компонент используется как базовый пример работы со списками, второй моделирует сложный участок высоконагруженного фронтенд-приложения со смешанной ответственностью и высокой инфраструктурной связанностью.

## Структура проекта

### Пример 1: Базовый компонент работы со списками

Демонстрация рефакторинга базового компонента с сетевой загрузкой и постраничным отображением данных. Компонент используется как пример сценария с ограниченным числом внешних зависимостей.

* `src/SingleComponent.vue` - исходная реализация на Vue 2 с использованием Options API. Логика работы с сервером и состояние формы тесно связаны в одном модуле.
* `src/MigratedSingleComponent/` - мигрированные реализации на Vue 3.
* `CompositionAPI/MigratedSingleComponent.vue` - компонент представления на Composition API.
* `CompositionAPI/composables/useMigratedSingleComponentLogic.js` - изолированная логика запросов и вычисления диапазона страниц.
* `OptionsAPI/MigratedSingleComponent.vue` - компонент представления на Options API с использованием composable.
* `OptionsAPI/composables/useMigratedSingleComponentLogic.js` - та же бизнес-логика, используемая в Options API-компоненте.

### Пример 2: Сложный составной компонент, моделирующий высоконагруженный сценарий

Демонстрация применения методики к компоненту со сложной инфраструктурной связанностью: смешением управления интерфейсом, бизнес-правил, фильтрации данных и взаимодействия с глобальным состоянием.

* `src/MultiComponent.vue` - исходная реализация на Vue 2. Компонент характеризуется жесткой связностью с хранилищем Vuex и зависимостью от глобального объекта `window`.
* `src/MigratedMultiComponent/` - мигрированные реализации на Vue 3.
* `CompositionAPI/MigratedMultiComponent.vue` - компонент представления на Composition API.
* `CompositionAPI/composables/useMigratedMultiComponentLogic.js` - бизнес-логика контроля доступа и фильтрации, вынесенная из компонентной оболочки.
* `OptionsAPI/MigratedMultiComponent.vue` - компонент представления на Options API с использованием composable.
* `OptionsAPI/composables/useMigratedMultiComponentLogic.js` - та же бизнес-логика, адаптированная для Options API-компонента.

### Тесты

Каталог `tests/` содержит набор сравнительных модульных тестов для исходных и мигрированных реализаций:

* `SingleComponent.spec.js` - тесты исходного компонента на Vue 2;
* `MigratedSingleComponentCompositionAPI.spec.js` - тесты версии Composition API;
* `MigratedSingleComponentOptionsAPI.spec.js` - тесты версии Options API + Composable;
* `MultiComponent.spec.js` - тесты исходного сложного компонента на Vue 2;
* `MigratedMultiComponentCompositionAPI.spec.js` - тесты версии Composition API;
* `MigratedMultiComponentOptionsAPI.spec.js` - тесты версии Options API + Composable.

## Запуск проекта и тестов

1. Установка зависимостей:

```bash
npm install
```

2. Запуск тестов:

```bash
npm test
```

3. Запуск сбора метрик:

```bash
npm run metrics
```

## Результаты миграции и количественные метрики

Для оценки результатов используются метрики тестирования и архитектурного качества, так как основная цель рефакторинга состоит в изоляции бизнес-логики, снижении связанности и упрощении сопровождения кода.

### Описание метрик

| Метрика | Описание | Единица измерения |
|---|---|---|
| Объем кода тестов | Количество строк исполняемого кода тестов без импортов, пустых строк и комментариев | строки |
| Время выполнения тестов | Среднее время запуска набора модульных тестов | миллисекунды |
| Необходимые зависимости | Количество внешних зависимостей, mock-объектов и имитаций, требуемых для тестирования | количество элементов |
| Обработка больших массивов | Тип реактивности, используемый для работы с данными | тип механизма |
| DCR | Dependency Coupling Ratio - сумма всех внешних зависимостей, необходимых для тестирования | абсолютное значение |
| TI | Testability Index - отношение строк бизнес-логики к затратам на тестовую инфраструктуру | коэффициент |
| CR | Code Reduction - изменение объема бизнес-логики после миграции | процент |

Примечание: объем кода тестов измеряется как количество строк исполняемого кода тестов. Импорты, пустые строки и комментарии не учитываются.

## Дополнительные количественные метрики качества архитектуры

Для более глубокого анализа эффективности методики миграции введены три специализированные метрики: DCR, TI и CR.

## Метрика 1: Dependency Coupling Ratio, DCR

DCR показывает количество внешних зависимостей, необходимых для тестирования единицы логики.

Формула:

```text
DCR = сумма имитаций UI + сумма модулей Vuex + сумма глобальных объектов + сумма подменных функций
```

### Данные DCR

| Компонент | Имитации UI | Модули Vuex | Глобальные объекты | Подменные функции | Общий DCR | Изменение |
|---|---:|---:|---:|---:|---:|---|
| SingleComponent, Vue 2 | 12 | 0 | 2 | 1 | 15 | исходное значение |
| MigratedSingleComponent, Vue 3 Options API + Composable | 0 | 0 | 0 | 1 | 1 | в 15 раз ниже |
| MigratedSingleComponent, Vue 3 Composition API | 0 | 0 | 0 | 1 | 1 | в 15 раз ниже |
| MultiComponent, Vue 2 | 23 | 1 | 3 | 4 | 31 | исходное значение |
| MigratedMultiComponent, Vue 3 Options API + Composable | 0 | 0 | 0 | 1 | 1 | в 31 раз ниже |
| MigratedMultiComponent, Vue 3 Composition API | 0 | 0 | 0 | 1 | 1 | в 31 раз ниже |

### Графическое представление DCR

```text
DCR, чем меньше значение, тем ниже связанность

Базовый компонент работы со списками
Vue 2 Options API                 15
Vue 3 Options API + Composable    1
Vue 3 Composition API             1

Сложный составной компонент
Vue 2 Options API                 31
Vue 3 Options API + Composable    1
Vue 3 Composition API             1
```

Вывод: после миграции коэффициент связанности снизился в 15-31 раз. Это показывает, что логика стала проверяться без воспроизведения полного внешнего контекста компонента.

## Метрика 2: Testability Index, TI

TI оценивает удобство тестирования через отношение объема бизнес-логики к объему теста и вспомогательной инфраструктуры.

Формула:

```text
TI = строки бизнес-логики / (строки теста + строки инфраструктуры)
```

Где строки бизнес-логики - это строки кода composable-функции или методов компонента, непосредственно участвующие в проверяемом сценарии. Строки инфраструктуры включают имитации компонентов, настройки Vuex, подмену глобальных объектов и конфигурацию mount.

### Данные TI

| Компонент | Строки бизнес-логики | Строки теста | Строки инфраструктуры | TI | Изменение |
|---|---:|---:|---:|---:|---|
| SingleComponent, Vue 2 | 87 | 72 | 17 | 0.98 | исходное значение |
| MultiComponent, Vue 2 | 232 | 69 | 33 | 2.27 | исходное значение |
| MigratedSingleComponent, Vue 3 Options API + Composable | 73 | 49 | 0 | 1.49 | в 1.5 раза выше |
| MigratedMultiComponent, Vue 3 Options API + Composable | 85 | 39 | 2 | 2.07 | на 9 процентов ниже |
| MigratedSingleComponent, Vue 3 Composition API | 107 | 49 | 0 | 2.18 | в 2.2 раза выше |
| MigratedMultiComponent, Vue 3 Composition API | 114 | 23 | 2 | 4.56 | в 2.0 раза выше |

### Графическое представление TI

```text
TI, чем выше значение, тем выше относительная тестируемость

Базовый компонент работы со списками
Vue 2 Options API                 0.98
Vue 3 Options API + Composable    1.49
Vue 3 Composition API             2.18

Сложный составной компонент
Vue 2 Options API                 2.27
Vue 3 Options API + Composable    2.07
Vue 3 Composition API             4.56
```

Вывод по TI: для базового компонента работы со списками Composition API показал наилучший результат, а Options API + Composable также улучшил показатель. Для сложного составного компонента Composition API дал значительное улучшение, тогда как Options API + Composable показал небольшое снижение TI из-за сильного сокращения объема бизнес-логики при сохранении минимальной инфраструктуры. Поэтому TI необходимо анализировать совместно с DCR, CR и временем выполнения тестов.

## Метрика 3: Code Reduction, CR

CR оценивает изменение объема бизнес-логики после миграции. Метрика показывает процентное изменение количества строк бизнес-логики по сравнению с исходной версией.

Формула:

```text
CR = ((Vue3 логика - Vue2 логика) / Vue2 логика) * 100%
```

Интерпретация:

* положительное значение означает увеличение объема кода;
* отрицательное значение означает сокращение объема кода.

### Данные CR

| Компонент | Vue 2 логика | Vue 3 Options API + Composable | CR Options API + Composable | Vue 3 Composition API | CR Composition API |
|---|---:|---:|---:|---:|---:|
| SingleComponent | 87 | 73 | -16.1 процента, сокращение | 107 | +23.0 процента, увеличение |
| MultiComponent | 232 | 85 | -63.4 процента, сокращение | 114 | -50.9 процента, сокращение |

### Графическое представление CR

```text
CR, изменение объема бизнес-логики

Базовый компонент работы со списками
Vue 2 Options API                 87
Vue 3 Options API + Composable    73, -16.1 процента
Vue 3 Composition API             107, +23.0 процента

Сложный составной компонент
Vue 2 Options API                 232
Vue 3 Options API + Composable    85, -63.4 процента
Vue 3 Composition API             114, -50.9 процента
```

Вывод по CR: отрицательное значение показывает сокращение объема бизнес-логики, но не должно автоматически рассматриваться как единственный критерий качества. Например, у SingleComponent полная миграция увеличила объем логики на 23 процента, но одновременно снизила связанность и повысила тестируемость. Поэтому CR используется как вспомогательная метрика и интерпретируется совместно с DCR, TI и прохождением тестов.

## Итоговый вывод по метрикам

### Composition API, полная миграция

Подход предпочтителен для:

* максимальной тестируемости;
* долгосрочной поддерживаемости;
* явного разделения состояния, вычислений и пользовательских действий;
* новых проектов на Vue 3;
* компонентов, которые можно безопасно перевести на новую архитектуру целиком.

### Options API + Composable, промежуточная миграция

Подход подходит для:

* поэтапной миграции существующих проектов;
* снижения связанности без полного переписывания компонента;
* унаследованных систем, где необходимо сохранить привычную компонентную оболочку;
* сложных компонентов, где важно сначала вынести бизнес-логику и снизить риск регрессии.

## Практическое значение

Результаты показывают, что миграция с Vue 2 на Vue 3 дает наибольший эффект тогда, когда она не ограничивается синтаксическим обновлением. Основной результат достигается за счет выноса бизнес-логики в composable-функции, явного ограничения зависимостей и проверки логики без полной инициализации компонентной оболочки.

Для базового компонента основной эффект выражается в снижении связанности и повышении тестируемости. Для сложного составного компонента эффект проявляется сильнее: уменьшается объем бизнес-логики, сокращается тестовая инфраструктура, ускоряются тесты и снижается риск каскадных ошибок при изменении кода.

## Рекомендация

Для новых проектов и полной переработки архитектуры предпочтителен Composition API, так как он обеспечивает лучший показатель тестируемости и более ясное разделение логики. Для действующих унаследованных проектов рационально применять промежуточный подход Options API + Composable, поскольку он позволяет постепенно снижать связанность и переносить бизнес-логику без резкого изменения всей структуры компонента.
